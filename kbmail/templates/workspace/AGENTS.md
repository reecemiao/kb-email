# kbmail workspace: agent instructions

This folder is a private knowledge workspace built from the user's Outlook mail, calendar and Teams
chats. Python (`kbmail` CLI) does all deterministic work; you do the reading, judging and writing.

- **Skills** in `.github/skills/` describe each job and appear as `/kb-*` commands (for example
  `/kb-sync`, `/kb-label`, `/kb-draft`). Load the matching skill before doing a job.
- **The KB Librarian agent** (`.github/agents/kb-librarian.agent.md`) bundles these instructions with
  a tool set that has no web access. Prefer it for work in this folder.
- **State:** a session-start hook (`.github/hooks/kbmail.json`) injects `kbmail status` when a session
  starts. If you don't see that context, run `kbmail status`; it always says what is due next.
- The `kbmail-cli` skill lists every command.

## Folder contract (who may write where)

| folder | you may | notes |
|---|---|---|
| `data/`, `state/` | read only | owned by kbmail; change them only through `kbmail` commands |
| `work/` | read; write only the `*.result.jsonl` files a batch asks for | queues generated by kbmail |
| `review/` | read; write `review/images/*.mmd` and descriptions when a skill says so | the user's to-do area |
| `raw/` | write only via `/kb-format` (formatted threads) | knowledge sources; never edit during wiki ingest |
| `wiki/` | write, following `wiki/SCHEMA.md` | the knowledge base |
| `config/rules.yaml`, `config/rules_journal.md` | write via `/kb-rules` | labeling rules + conclusions |
| `drafts/` | write | email drafts; kbmail never sends mail |
| `kbmail.yaml`, `.env` | only when the user asks | settings (`kbmail config show` explains them) |

## Working rules

- Run CLI commands in the terminal (`kbmail ...`). Use `kbmail show <id> --thread` to read a message or
  thread, `kbmail mail "<query>"` to search mail, `kbmail wiki search "<query>"` to search the wiki.
- Output files must follow the exact format the batch/skill specifies (JSON Lines = one JSON object
  per line, no surrounding array, no code fences). Then run the matching import command and fix any
  errors it reports.
- Areas and their descriptions are in `kbmail.yaml`. The only valid labels are those areas and `others`.
- Process large queues in chunks and save results after each chunk, so work is never lost. When
  subagents are available, give each batch to a subagent, so the main conversation stays small.
- When you don't understand something (acronym, system, person, missing context, a document you need),
  don't guess: record it with `kbmail questions add "<question>" --context "<where you saw it>" --step <skill name>`.
- Privacy: content is confidential. Never send it to external services or web searches. Never copy
  credentials, personal data unrelated to work, or HR/medical details into raw/ or wiki/.
- Language: write knowledge in the language of the source unless the user asks otherwise; keep names
  in their original script and add romanized aliases where useful.
- If vision is disabled (`copilot.vision: false`, see `kbmail config show copilot`) do not try to
  interpret images; the user describes them in `review/images/descriptions.yaml`.
